# 视频动态乐谱转谱流水线技术规格说明书

**文档状态**：现行有效 (Active)  
**目标模块**：`video2score.*`  
**遵循约定**：文中使用 `MUST`（必须）、`MUST NOT`（禁止）、`SHOULD`（建议）表示规范性约束。

---

## 1. 范围与目标 (Scope, Goals & Non-Goals)

### 1.1 问题与背景
动态乐谱视频（B 站、YouTube 上的电声贝斯、吉他谱视频）存在画面滚动、播放光标、动画背景与翻页特效。  
直接截图去重会失效：连续多个小节音符相同时无法区分；播放光标与动态背景会破坏识别特征。  
本流水线将视频全自动转换为两套产物：
1. **重新排版的高清截图 PDF**：去色、去光标、统一线距；
2. **小节库与乐理文件**：提取音符、品位与节奏，导出 MusicXML 与 Guitar Pro 文件。

### 1.2 系统目标 (Goals)
- **G1 (全自动转换)**：输入视频链接（B 站、YouTube 等）或本地视频文件，自动完成下载、分帧、找小节、去重清洗与导出。
- **G2 (无损去重与顺序保证)**：基于帧间位移追踪小节，禁止按长相去重，确保音符完全相同的小节不丢失、顺序不错乱。
- **G3 (背景与光标消除)**：利用多次分散观测的逐像素投票机制，彻底消除播放光标、高亮块与动态背景。
- **G4 (符号与技巧识别)**：准确识别 TAB 品位、五线谱音符时值，以及击勾弦、推弦、滑音、闷音等常用演奏法。
- **G5 (单机轻量运行)**：提供只用 Python 标准库的本机 Web 界面，支持打包为独立客户端；默认端口被占用时由系统另分配空闲端口，具备本机安全防护。

### 1.3 明确不做的范围 (Non-Goals)
- **NG1 (通用纯五线谱识别)**：当前不处理没有 TAB 的纯五线谱多声部复杂交响/钢琴乐谱（`omr.py` 仅为实验接口，不接入主线）。
- **NG2 (实时流式处理)**：系统为离线批处理设计，不保证 1 秒以内的低延迟实时转码。
- **NG3 (修改第三方源码)**：对 `alphaTab`、`Puppeteer`、`yt-dlp` 等外部工具一律作为黑盒调用，不维护私有修改分支。

## 2. 架构与流程 (Architecture & Flow)

### 2.1 处理链路

```text
视频源
  │
  ├─ 0. 判断谱面类型 (Survey)
  │    survey.survey         --> 均匀抽 24 帧：谱带还是整页视图、线距多大、要不要放大（试读定）→ 识别模式（见 2.3）
  │
  ├─ 1. 找谱面与切小节 (Vision & Slice)，默认每 0.33 秒取一帧
  │    frames.score_box      --> 找谱面区域（整页白纸，或横贯画面的谱带）；要放大的放大后再找
  │    staff.find_systems    --> 找谱线（4/5/6条等距长横线；五线谱与 TAB 配对；找小节线）
  │    measures              --> 切出两侧都有小节线的完整小节；提取小节号区域 ROI
  │
  ├─ 2. 跨帧追踪与排号 (Tracking & Ordering)
  │    track.Tracker         --> 算相邻帧整体位移；小节匹配到已有槽位，没匹配的开新槽位
  │    ocr / numbers         --> 局部对比度二值化、投影切分、灰度模板匹配读小节号
  │    order.arrange         --> 拆开误并、按最长递增子序列排序、补齐漏号、剔除离群号
  │
  ├─ 3. 清洗与排版 (Cleaning & Layout)
  │    clean.render_slot     --> 帧间对齐、彩色像素转为白纸、逐像素中位数投票、重画谱线
  │    layout / header       --> 统一线距，行宽微调拉齐，输出 score.pdf
  │
  └─ 4. 识别与导出 (Recognition & Export)
       tab / rhythm / marks  --> 读弦线品位、符干符杠时值、连音、滑音、击勾弦、拍弦
       tabscore              --> 拍号守恒校验、组装双行谱（五线谱 + TAB）→ score.musicxml
       gpfile / engrave      --> 导出 .gp / .gpx / .gp5，通过 alphaTab 输出排版 PDF
```

### 2.3 谱面类型与识别模式

正式逐帧找小节之前，`survey` 在起止时间内均匀抽 24 帧，判断谱面是哪一种，后面按对应的模式处理。结果记在 `manifest.json` 的 `sampling.mode`。

| 类型 | 判据 | 模式 |
|---|---|---|
| **谱带** (`band`) | 横贯画面的一行谱（大多数动态谱视频）。 | 谱面框按谱线找，框住线数最多的一条谱带。 |
| **整页视图** (`page`) | 打谱软件页面视图的录屏：一半以上的抽样帧里有包住谱线的白纸，去掉两侧不够白的列以后左右都碰不到画面边沿（两侧是软件界面）。不按每帧几行谱判断：谱带的框有时也框进两三行。 | 谱面框框整张白纸：不要求四个角都是深色界面（窗口角上有图标）；纸可以碰到画面上下沿；上下露出两张纸时一起框；最上、最下那行谱的线数比别的行少（被画面边沿切掉一截）时这一帧不收。 |

**要不要放大**：谱面小时数字、滑音线、连线挤在两三个像素里，各处按线距定的门槛（按 1080p、线距 15 像素左右的视频调过）都不准，放大到线距约 15 像素再识别常常准得多；但同样大小的谱面，有的放大后反而更差（原图本来清楚，放大只是糊开）。所以不按线距一刀切，而是实测：线距不到 15 像素（放大不到 1.05 倍的不试）时，从抽样帧里挑 8 帧，按原尺寸和放大后各切一遍小节、用通用模板读 TAB 品位和小节号，数相关值 $\ge 0.8$ 的读数；放大后比原尺寸多两成以上才放大（放大后要处理的像素多好几倍，慢得多）。两种尺寸各读出多少记在 `sampling.mode.trials`。放大时找到谱面框以后把框里放大再找小节，后面各步照常，坐标都按放大后的整帧算。放大后原图一个像素的笔画有两三个像素粗，五线谱上找空心符头时，符干末端允许伸到符头中心再往里 0.4 个线距，环的位置按 0.05 个线距一步挪（一般的谱是 0.3、0.1：背景杂的视频里这样会多找出假的空心符头；0.3 是因为符干常和环贴着它的那道竖笔连成一道，量出的末端会伸过中心）。

### 3.1 作业目录结构 (`jobs/<id>/`)

每次运行创建独立目录（`<id>` 格式为 `年月日-时分秒-4位随机hex`）：

```text

│   ├── 0001.png               # 清洗重绘后的小节图（供拼接排版）
│   ├── 0001_raw.png           # 参考原帧灰度图（供识别投票）

├── score.pdf                  # 截图清洗重排 PDF

├── score.gp / .gpx / .gp5     # 导出的 Guitar Pro 文件

└── tab_issues.json / .txt     # 需人工核对的可疑小节明细（界面用 json，txt 给人看）
```

## 4. 跨帧追踪与异常处理 (Tracking & Edge Cases)

### 4.1 整体位移估算与匹配
1. **候选位移**：对比相邻两帧中长相相同的小节，算出可能的整体平移量。
2. **位移评分**：
   - 匹配上的小节越多，得分越高；
   - 出现小节号冲突的扣分；小节号冲突超过半数的位移直接废弃；
   - 画面往前走优先于往后走；
   - 往回走的位移如果只有单一小节支撑，不予采信。
3. **降级策略**：
   - 和上一帧对不上时，往前检索最近几帧；
   - 仍对不上（触发翻页）时，拿当前帧开头和已收录序列末尾比对，至少连续对上两个小节才接上。

### 4.2 边界工况处理规则

| 工况 | 识别特征 | 处理规则 |
|---|---|---|
| **小节号冲突** | 两帧都读出了清楚的小节号，但号码不同。 | 绝对不配对；该位移方案直接丢弃。 |
| **光标把小节切开** | 谱面没动，但某一小节因光标遮挡对不上上一帧。 | 往前几帧找同一位置、长相完好的小节接上。 |
| **个别小节线距异常** | MV 画面里的横条背景被误判为谱线。 | 只丢弃线距异常的那几个小节；整帧都异常才将整帧视为缩放废弃。 |
| **小节号出现断档** | 整理后出现序号跳空（如 32 直跳 36）。 | 到只出现过一两帧的碎片观测中找回（`order.rescue`），只补齐、不篡改已有小节。 |
| **结尾淡出截断** | 视频在最后几个小节淡出，画面只露出一两帧。 | 碎片中序号正好紧接末尾、至少出现两帧的，依序追加到结尾。 |
| **密集加线干扰** | 低音区密集十六分音符下方的短加线被误当成第 6 根谱线。 | 加线比正常谱线稀疏、单段极短。存疑的 6 线组降低优先级，优先使用偏移一线的 5 线组。 |
| **五弦 TAB 与五线谱** | 一行里上下两组都是 5 条线。 | 下面一组线距更大（>15%）时判为 TAB；只有一组 5 条线的纯五弦 TAB 用 `--notation tab` 手动指定。 |
| **台标盖住小节线** | 画面角上固定的半透明白色台标（如"小雨贝斯谱"）盖掉五线谱最上面一截，落在台标底下的小节线在五线谱上只剩七八成高。 | 配对那一组（TAB）上有整根的线时，五线谱上贯穿六成就算；否则两个小节并成一格，或者整小节丢掉。 |
| **虚线小节线** | 小节线垂直断续，只出现在谱线行之间（GP 自由节拍）。 | 竖线墨迹占比合适、五线谱与 TAB 同列对齐、色调与谱线一致时才收。 |
| **翻页翻到一段长得一样的反复** | 谱面很小（线距七八个像素）时小节号读不准，翻页后的新一行和旧一行音符完全相同，会被当成往上挪了一行。 | 挪动了的位移里，两边都读出号的配对中号不一样的有两对以上、还比一样的多，就不采信（一个号是另一个号的尾巴，如 46 与 146，算一样）；画面没动时不用这条。 |
| **整页视图翻页时露出两张纸** | 上一页的末尾和下一页的开头同时在画面里，下一页碰到画面下沿。 | 整页模式下两张纸一起框；中间的灰缝在小节上下沿检测处挡掉。被画面边沿切掉一截的行（只露出五线谱或只露出 TAB）这一帧不收。 |
| **跨小节线的弧线** | 连线、连奏滑音的弧从这一格的音一直画过小节线，清洗时碰到小节图边缘。 | 谱表外碰边的墨块一般是邻格截进来的残块、要删；纯黑的细弧（比一个线距宽、不到一个线距高、墨稀）伸进格里一个线距以上的留着。 |
| **背景插画渗入号区** | 动态插画透进小节号区域，每帧都在变。 | 只比对细笔画；只要两边都读出了相同号码，图像微小差异不算冲突。 |

## 5. 小节号识别与排序 (OCR & Ordering)

### 5.1 小节号切分与识别
1. **自适应提取笔画**：阈值随局部对比度动态调整。笔画横向适当膨胀连成一个数字。贴着 ROI 边缘的残画直接丢弃，防止半个 "2" 误判为 "1"。
2. **垂直投影切字**：空白处直接切开；连在一起的两位在最窄笔画处二次切开。
3. **灰度模板匹配**：缩放到 20×12 像素，与模板库做归一化互相关。**全流程使用灰度矩阵乘法，不做硬二值化**，保证 12 像素小字的斜笔不出现断裂。
4. **行首第一小节特殊处理**：首小节号码通常印在谱号、调号、拍号后面。常规区域读不出时，向右偏移 1~4.5 个线距重新切块读取。
5. **单曲专属自适应学习**：第一轮读完后，挑出前后连续（$n-1, n, n+1$）的置信样本，按类别平均生成本视频的专属字形模板，对低置信度槽位复读一遍。

### 5.2 基于递增子序列的时序整理
1. **拆开误并**：一个槽位若同时包含两个不同的小节号且票数相当，依观测帧拆分为两个独立槽位。
2. **递增骨架排序**：提取全局置信度最高的小节号最长递增子序列（LIS）作为基准骨架。未在骨架上但置信度高的小节挪到合适位置；重复的同号小节合并。
3. **容量过滤**：小节号 $p$ 与 $q$ 之间最多只能容纳 $q - p - 1$ 个无号小节，超额的删掉。
4. **线性补号与离群清除**：前后号相差为 2 时，中间无号小节直接补上中间值；突增 50 以上且接不上后文的孤立号直接清除。

## 6. TAB 与节奏识别 (Tablature & Rhythm)

### 6.1 判定规则一览

| 记号 | 视觉判据标准（线距 $S_p$ 口径） | 输出到 MusicXML |
|---|---|---|
| **拍号** | 小节开头上下叠着的两个粗体数字，分母只在 2/4/8/16 中选取；分母撑满下半个谱表，下端离最下面那条线不到半个线距；分子分母上下对齐，中心横向差不到 0.35 个线距（小节线或调号后紧挨着的八分音符，粗的符尾头在符头右上方，不算）。 | `<time>` |
| **调号** | 紧跟谱号后：升号为双竖笔（间距 $<0.6 S_p$），降号为单竖笔加圆肚。清洗图上认不出时，行首小节（有谱号）看各帧原图，过半数认出同一个调号就用。 | `<key>` |
| **调弦** | 行首前缀图每条弦高度最右侧字母，在标准调弦 $\pm 2$ 半音内匹配。 | `<staff-tuning>` |
| **速度** | 第一小节上方 "♩ = 数字"：先找等号，再读右侧数字。 | `<sound tempo>` |
| **品位** | 只在弦线附近找字；抹去垂直符干和小节线，被弦线切断的笔画拼回。 | `<string>` / `<fret>` |
| **括号延音** | TAB 上带括号的数字，代表延音。 | 延音线，不新起音 |
| **闷音 (Mute)** | TAB 上为 X；五线谱上 X 符头中心交叉，无实心/空心核。 | `<notehead>x</notehead>` + `<play><mute>` |
| **滑音 (Slide)** | 倾斜线段：按高低端与符头高度差区分滑入/滑出；带 "sl." 或弧线为连奏。"sl." 在整段斜线（到同一根弦上的下一个音或小节线）上方都找：跨小节线的连奏滑音斜线很长，"sl." 离斜线中点能有两三个线距；s、l、点粘成一块时按"左边几列只有下半截有墨、右边一道从顶到底的竖笔"认。斜线和后一个数字分在一组、前一个同弦的音不到两个字高远时，算两音之间的滑音。 | `<slide>` / `<slur>` |
| **击弦/勾弦** | 跨音符弧线（中粗两端尖）：后音品位升高为击弦，降低为勾弦。 | `<hammer-on>` / `<pull-off>` |
| **装饰音** | TAB 上小一号的数字（高宽比 $\ge 1.3$）。 | `<grace slash="yes"/>` |
| **跳音** | 符头另一侧 $0.5 \sim 2 S_p$ 处的孤立实心小圆点。 | `<staccato/>` |
| **重音** | 符头另一侧 $1.2 \sim 4.5 S_p$ 处的尖朝外 `^` 或尖朝右 `>`。 | `<strong-accent/>` / `<accent/>` |
| **拍弦/勾弦** | TAB 上方正对音符的 "S"（拍）或 "P"（勾）字母。 | `<?GP <root><bass-attack...>>` |
| **推弦** | TAB 上方垂直实心箭头，上方小数字标明推音幅度；不往上找过五线谱下沿（压在最下面那条线上的实心符头像箭头尖）。五线谱上从被推的音到箭头尖这段认出的"休止符"是推到的音的小符头和升降号，去掉。 | `<bend><bend-alter>` |
| **符杠/符尾** | 符干端部相连的横向粗墨迹段（约 $0.45 S_p$ 厚）；整列贯穿的长竖线为光标，剔除。 | 符杠分组；单出小钩写 `forward hook` |

### 6.2 核心消歧要点
- **识别看原图，不看清洗图**：清洗图里 1~2 像素宽的细笔画会被投票投淡，因此字符识别必须基于单帧原始灰度图（`NNNN_raw.png`）。
- **清洗图补漏与仲裁**：各帧投票后再读一遍清洗图。投票里没有的音，清洗图读得有把握就补进来；投票读得没把握、或只读出两位数里的一位时，清洗图在同一处读得很有把握（NCC $\ge 0.85$）才换成清洗图的读数；其余只补不改。
- **品位的专属模板**：整首曲子的候选字形按形状聚类，每类定一个数字做成专属模板。和已经定好的一类平均字形几乎一样（相关值 $\ge 0.92$）的类跟它定同一个数字：放大过的小谱面上同一个数字会因为落在原图像素格上的位置不同分成好几类，单独定时把握小的那类可能被认成别的数字（8 认成 6）。
- **符头配符干**：几根符干都挨着符头时，先要摆法对的（朝上的画在符头右边、朝下的画在左边），再比远近：两道符尾挨得近、笔画粗时右端会连成一道竖笔。
- **拍号守恒修正**：小节时值超出拍号时，依序尝试：去掉误读的占位休止符、连杠音由四分改八分、单一三连音或附点修正。仍超出的记入 `tab_issues.json`。
- **延音 vs 重复同音**：五线谱连续同高度音符，看两音之间是否有延音弧线。有弧线为延音；无弧线为重复弹奏，复用前音品位，不连延音线。
- **画面无速度时根据视频推算**：利用滚动/翻页的时间差除以小节拍数，取中位数推导 BPM；单复拍混用时对比四分音符与八分音符方差确定基准拍。

## 7. 清洗排版与导出 (Cleaning, Layout & Export)

### 7.1 图像清洗与重绘
1. **去光标与高亮**：彩色像素（光标、变色音符）强制视为空白纸色。
2. **多帧中位数投票**：各帧刚体对齐后，先全局投票去粗影，再选最干净的 3~5 帧重投；最干净帧独有的 1~2 像素细符干若有支撑则予以补回。
3. **谱线重绘**：抹去原图断续杂乱的谱线，五线谱重绘为光滑长直线，TAB 弦线在文字包围盒处精确断开。

### 7.2 多格式导出实现
- **`score.pdf`**：统一物理线距，小节首尾无缝对接，按 A4 纵向排版分页。
- **`.gp` (GP7/8)**：写入 ZIP 容器的 `Content/score.gpif`；弦号以低音粗弦为 0；推弦每半音 50 单位。
- **`.gpx` (GP6)**：将 `score.gpif` 写入模拟的 BCFS 块设备文件系统，封装为 BCFZ 数据包。
- **`.gp5` (GP5)**：通过 `pyguitarpro` 写入；文字统一转为 GBK 编码。
- **`score_engraved.pdf`**：通过 Node.js 调用 `alphaTab` 渲染出分块 SVG，按 A4 分页拼成网页，再由 Node 里的 Puppeteer 控制自带的 chrome-headless-shell（固定版本）用 `page.pdf()` 打印为矢量 PDF。从源码运行时没有自带浏览器，用 `python packaging/build.py --browser` 下载同一版本，或用本机 Chrome。

## 8. 本地服务与安全机制 (Local App & Security)

- **服务绑定**：`python -m video2score app` 仅监听本机回环地址 `127.0.0.1`（默认端口 17865，被占用时由系统另分配空闲端口），禁止监听公网地址。
- **临时凭证校验**：每次启动生成高强度随机 Token，所有前端 API 请求必须带 Token。
- **防 DNS 重绑定**：后端严格检查 HTTP `Host` 请求头，非 `localhost` 或 `127.0.0.1` 请求直接返回 403。
- **路径穿越防御**：所有作业文件访问必须限制在 `jobs/` 目录树内，禁止 `../` 越界。
- **文件软删除**：Web 端删除乐谱操作仅将文件夹移动到 `data/trash/`，不执行物理永久删除。

## 9. 测试验证与合规矩阵 (Verification & Compliance)

### 9.1 测试体系
测试代码、测试素材（第三方视频截图）和端到端基准用的视频、原谱都只保存在开发者本地，不随仓库公开。

- **合成单元测试** (`test_core.py`, `test_omr.py`)：纯代码生成合成乐谱，验证谱线提取、小节线贯穿、光标消除与技巧解析。
- **真实小节号回归** (`test_ocr.py`)：使用 164 块真实视频截取的小节号图片测试，要求**错误率为 0，读出率 $\ge 95\%$**。
- **端到端原谱基准** (`bench-pdf`)：对 11 首含标准原谱的真实视频，按音符序列做动态规划对齐，报告漏节、多节及准确率，并用 `inkcheck.py` 检查墨迹丢失与串格。
